# data-tools

Seven small CLI converters I kept rewriting in throwaway scripts. Now they live here.

The pain point: moving data between the formats you actually get handed (Excel exports, JSON dumps, YAML configs) and the formats you actually want (CSV for a human, Parquet for a query engine). Every tool I found either wanted to be a framework or lost my nested keys silently.

## Install

Core tools only need PyYAML:

```bash
pip install -e .
```

For the Parquet and Excel converters you also need pandas/pyarrow/openpyxl:

```bash
pip install -e ".[data]"
```

Tested on Python 3.9 through 3.12, macOS 14 and Ubuntu 22.04. Windows works but the CSV files get a UTF-8 BOM by default so Excel doesn't mangle accents.

## The tools

### json_to_csv.py

Flattens nested objects with dots, dumps arrays as JSON strings in one cell, auto-detects JSONL.

```bash
json-to-csv examples/sample.json -o users.csv
```

Output columns for `examples/sample.json`:

```
id,name,email,active,signup_date,plan.tier,plan.seats,plan.renewal,tags,last_login,monthly_spend
1042,Ada Lovelace,ada@example.org,True,2023-11-02,pro,3,2024-11-02,"[""analytics"", ""beta""]",2024-03-14T09:12:44,49.0
```

If you'd rather keep nested objects as one JSON blob: `--no-flatten`.

### yaml_to_json.py

Handles multi-document YAML. A single doc becomes an object, several become an array.

```bash
yaml-to-json k8s/deployment.yml --indent 2
yaml-to-json multi.yml --ndjson          # one JSON per line
```

Needs pyyaml. If it's missing you get a one-line error, not a traceback.

### csv_to_parquet.py

```bash
csv-to-parquet big.csv -o big.parquet --compression zstd
csv-to-parquet big.csv --dtypes types.json --chunk 100000
```

`types.json` is just `{"zip": "string", "amount": "float64"}`. Use it when pandas guesses wrong, which it will for anything with leading zeros.

### excel_to_csv.py

```bash
excel-to-csv book.xlsx                       # first sheet
excel-to-csv book.xlsx --sheet "Q3 2024"
excel-to-csv book.xlsx --all-sheets -d out/  # one CSV per sheet
```

**Gotcha:** formulas are not evaluated. openpyxl reads the cached value, and if the workbook was generated by a script (never opened in Excel) that cache is often empty, so you get NaN. Open and re-save the file in Excel or LibreOffice first.

### dedup_json.py

Dedupes on the whole record by default, or on a subset of keys.

```bash
dedup-json events.jsonl --keys id --keep last -o events.clean.jsonl
```

String comparison strips surrounding whitespace, so `" Ada "` and `"Ada"` are the same record. `--keep last` is what you want when later rows are corrections.

### concat_csv.py

Stacks CSVs whose columns don't line up.

```bash
concat-csv exports/*.csv -o all.csv --add-source --dedupe
```

Default is the union of columns, blanks where a file didn't have one. `--intersect` keeps only columns present everywhere.

### schema_infer.py

Reads a sample and tells you what's actually in each column. Type vocabulary is small on purpose: integer, number, boolean, date, datetime, string, mixed, empty.

```bash
schema-infer dump.csv
```

```
| column | type | null % | examples |
| --- | --- | --- | --- |
| id | integer | 0.0 | `1042`, `1043` |
| signup_date | date | 0.0 | `2023-11-02` |
| tags | string | 0.0 | `["analytics", "beta"]` |
```

`--format json` if you want to consume it.

## Gotchas

- **Leading-zero IDs become integers.** `007` is classified as `string` by schema_infer, but `pandas.read_csv` will happily turn it into `7`. Pass `--dtypes` with `string` for those columns. Bit me on a zip-code column once.
- **BOM.** Output CSVs start with a UTF-8 BOM so Excel opens them correctly. Pipe them into another tool that doesn't expect it and you'll see a stray `\ufeff` on the first header. Use `--no-bom` on json_to_csv, or strip it downstream.
- **json_to_csv drops nothing, but it also doesn't explode arrays.** One array cell per row. If you need one row per element, pre-process the JSON.
- **Very large files.** csv_to_parquet has `--chunk`; the JSON tools load the whole file into memory. A 2 GB JSONL will hurt.
